# 人机协作原则与 Agent Skills

这个仓库面向与智能体（Agent）共同完成软件开发、科研分析、文档和复杂日常任务的人，整理可追溯的协作经验，并提供五个能够独立安装的 Skill。Skill 是一组按需加载的任务指令及参考资料，用来帮助 Agent 在特定情境中采取更合适的协作行为。

## 为什么需要这个项目

Agent 能够调用工具、编写代码和查阅资料，但用户仍可能花很多时间纠正目标、催促推进、理解汇报、追问证据和恢复长任务。一个任务即使产生了很多文件，也可能没有解决用户最初的问题；一段汇报即使流畅，也可能掩盖尚未验证的部分。

这些问题贯穿协作全过程：开始时需要判断哪些歧义值得问；执行时需要控制未经验证便扩大的工作范围；沟通时需要适配读者；交付时需要让声明对应证据；跨会话时需要保存并核实状态。五个专题由此形成，分别承担一段清楚的职责。

## 目标、产物与预期效果

项目目标是降低误解、返工、无效确认、阅读压力和恢复成本。主要产物是五份完整研究报告、五个独立 Skill，以及两类平台常驻模板。

| 协作问题 | 对应 Skill | 预期行为 |
| --- | --- | --- |
| 用户意图不完整，提问又可能过多 | `intent-clarification` | 先调查，只问关键歧义，帮助决策，及时退出澄清 |
| 大跨度执行、频繁确认、无效重试 | `incremental-execution` | 按可验证成果推进，区分通知与审批，受阻时留下恢复条件 |
| 汇报难读、黑话多、解释深度不合适 | `clear-communication` | 自然直述，结果优先，依据知识广度和深度安排解释 |
| 完成声明超出证据，审查缺少闭环 | `evidence-based-delivery` | 区分状态，验证原始目标，独立审查后核实反馈 |
| 压缩后遗漏、跨会话重复、沿用旧状态 | `long-task-continuity` | 保存关键事实，恢复前核查产物，按状态管理上下文 |

这些是预期改善方向。项目依据公开文档、开源实现和工程案例归纳经验，没有开展自有对照实验或基准实验，也没有给出量化收益。格式校验通过说明 Skill 文件符合结构要求，实际行为仍取决于模型、运行框架、工具和任务。

## 能力边界

语言模型负责理解与推理，运行框架负责工具调用、权限、压缩、会话恢复及可能的循环检测。本仓库补充协作规范：何时调查、询问、验证、报告和恢复。文本规则无法代替工具权限或保证推理正确。

规则应有实际作用、触发条件与适用边界。可以适度重申有价值的默认行为，但不强制每个任务都规划、访谈、写状态文档或派审查 Agent。规则也应随平台能力与真实反馈更新或删减。

## 如何使用

先选与任务相关的一个或多个 Skill，把对应的整个目录安装到目标 Agent 当前支持的 Skills 位置，保留入口和内部参考文件。安装位置与自动发现能力由目标平台决定，单纯下载本仓库不会自动让所有 Agent 加载它。

然后按需要将平台模板中的常驻偏好合并到自己的项目指令中。已有 `AGENTS.md` 或 `CLAUDE.md` 应人工合并，保留项目约束；不要用模板整份覆盖。根目录的 `AGENTS.md` 只供维护本仓库使用。

例如，播放器倍速功能可能同时需要澄清关键体验、分阶段实现、按原始需求验证以及清楚汇报。若任务能在一个会话完成，就没有必要加载长任务恢复流程。五个 Skill 允许共同作用，不要求固定调用顺序，也不强制彼此依赖。

## 来源与许可

研究内容依据用户提供的五份专题共识整理，保留其中公开参考来源；原文中的阶段状态和讨论性叙述改写为独立知识文档。来源、经验和设计建议的证据边界见研究方法。

当前尚未选定公开复用许可证，详见 `LICENSE`。所有说明性正文使用中文；目录名、Skill 标识、格式字段和产品名称保留必要的原写法。
