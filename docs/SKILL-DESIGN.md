# Skill 设计与平台适配

## 设计目标

仓库同时服务两类读者。希望理解方法的人需要完整问题、实践与推理链；希望直接使用的人需要简洁规则、清楚触发条件和可独立安装的目录。研究报告、Skill参考、Skill入口和常驻模板分别满足这些需要。

## 五个独立 Skill

- `intent-clarification`：需求澄清机制。
- `incremental-execution`：任务规模与执行节奏。
- `clear-communication`：自然语言沟通与信息表达。
- `evidence-based-delivery`：完成状态与证据表达。
- `long-task-continuity`：长任务状态管理与上下文恢复。

每个目录包含 `SKILL.md` 和 `references/practices.md`。入口使用规范要求的 `name` 与 `description` 字段；标识保持小写英文和连字符，描述和正文使用中文。描述说明做什么、何时使用以及容易误触发的边界。参考文件保存逐条解释、案例和来源，并在入口说明何时读取。

各 Skill 可共同作用，但运行所需信息均在自己的目录内，不依赖根目录研究报告或其他 Skill。参考资料与研究报告允许必要重叠，以同时保证独立使用和完整研究；规则含义必须同步维护。

## 触发机制与渐进加载

Agent通常先获得名称和描述，任务匹配后读取入口，再按需读取详细参考。实际发现和加载机制由目标运行框架实现，本仓库不保证所有平台都会自动识别下载目录。

| Skill | 触发时机 | 简化边界 |
| --- | --- | --- |
| 需求澄清 | 存在影响目标、体验、风险或验收的重要歧义 | 明确任务直接执行，可查事实先调查 |
| 增量执行 | 多成果、多阶段或需要控制未经验证的工作范围 | 单步任务无需详细计划 |
| 清晰沟通 | 复杂解释、跨领域研究、长报告或任务交付 | 普通短答无需固定章节 |
| 证据交付 | 实际产物需要完成声明、验证或复杂复核 | 普通讨论无需交付流程 |
| 长任务连续性 | 压缩、交接、长期状态或可疑退化 | 短任务无需完整记忆库 |

## 常驻规则的职责

自然、直接、诚实的表达和授权边界具有跨任务价值，可以在极简常驻模板中保留。复杂解释中的C1–C7仍放在独立Skill里，以便在需要时获得完整指导。常驻规则不应收纳全部研究报告或任务日志。

根目录 `AGENTS.md` 管理本仓库维护；`adapters/agent/AGENTS.md` 供支持该格式的Agent使用；`adapters/claude-code/CLAUDE.md` 供Claude Code使用。两份模板表达一致偏好。为便于单文件复制，当前保留各自完整文本，合并时注意同步；无需因导入相对路径改变而额外复制整个仓库。

## 安装与组合

使用者选择整个Skill目录安装到平台支持的位置，再将适配模板合并入已有项目规则。不要覆盖已有项目约束。安装后可用真实任务观察是否匹配到需要的Skill，单独检查入口是否可读、参考是否存在以及是否误加载不相关流程。

例如，播放器倍速功能可能先澄清关键体验，再按成果实现，随后验证和独立复核，最后清楚交付。长任务规则只有在持续时间或恢复风险需要时介入。这个例子展示职责组合，不规定固定顺序。

## 可维护性与校验

维护时先核对编号和语义，再同步研究、参考、入口与索引。结构检查包括元数据、命名、内部链接与自包含性；内容检查包括原始需求覆盖、来源边界和误用风险。格式通过不等于自动触发正确，也不等于行为效果已经验证。

当前五个Skill不需要脚本或输出素材，因此不创建占位目录。出现真实可复用需求时再添加相应资源，保持入口能按问题引导到必要材料。
